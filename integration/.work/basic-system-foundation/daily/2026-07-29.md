# 2026-07-29 작업 기록

- 작업 ID: `basic-system-foundation` 3B 후속 보완 및 4단계 공 선택·조준·발사·반복
- 담당 역할: 메인 구현·서브 에이전트 병렬 구현·독립 교차 QA
- 환경과 기준 커밋: `feature/core-system`, `ac2d5e5` 기반 미커밋 작업 트리; macOS Apple M1; Godot `4.7.1.stable.official.a13da4feb`; Desktop Compatibility

## 구현 내용

- 보드 ID로 `stages/boards/content/<board_id>/` 아래 보드 설계도·보기 설정·웨이브 배치표를 함께 복제하고 기존 경로 충돌을 거부하는 저장 규칙을 추가했다.
- `BoardAuthoring2D` 루트 변형을 항등값으로 바꾸고 단독 실행에서만 화면 중앙에 놓아, 씬 인스턴스 루트 변형 경고 없이 재사용하게 했다.
- 영문 GDScript·`.tres` 속성명을 유지하면서 Godot 기본 속성 편집기에 한국어 이름·설명·단위를 붙이는 공용 인스펙터 표시 계층을 추가했다.
- 표준 공 원형과 차원 독립 물리 설정, 웨이브 공 슬롯 1~3개, 조준 설정, 발사 명령·계산 결과, 발사 생명주기와 종료 결과를 구현했다.
- `direction_keys`와 `mouse` 두 조준 방식을 `.tres` 하나로 교체하고 두 방식 모두 `Space`로 발사하게 했다.
- 현재 2D용 `RigidBody2D` 어댑터를 구현하고, 차원 독립 보드 좌표·속도를 현재 2D 물리 좌표로 바꾸는 변환을 조립 계층에서 주입했다. 미래 3D 어댑터는 같은 명령·결과 계약을 소비할 수 있다.
- 실제 웨이브 화면에 공 선택→조준→발사→드레인 또는 보드 밖 종료→다음 공 선택 반복을 연결했다. 가져온 공을 모두 사용해도 4단계에서는 스코어 성공·실패를 판단하지 않는다.
- 공 진행 중 방향키는 상대 위치에 따라 고유 배정된 플리퍼 선택, `Space`는 플리퍼 작동 요청으로 라우팅했다. 실제 움직임은 5단계 범위로 남겼다.

## 구현 결과

- 기본 목업 웨이브는 독립 슬롯 `ball_slot_1~3`에 표준 공 세 개를 제공하며 1~3개 목록만 유효하다.
- 숫자키와 네 방향키로 남은 공을 선택하고 첫 `Space`는 선택 확정, 두 번째 `Space`는 발사, 공 진행 중 `Space`는 플리퍼 요청 하나만 만든다. 방향키 조준에서는 방향키를 길게 누르는 동안 각도·세기가 반복 조절된다.
- 마우스 조준은 58°로 투영된 화면 위치를 보드 평면으로 역변환해 방향·세기를 만들며, 방향키 조준은 입력 한 번당 승인된 각도·세기 변화량을 사용한다.
- 활성 공은 0개 또는 1개이며 고속 이동용 연속 충돌 검사, 최대 직선·회전 속도 제한과 보드 밖 안전 종료를 적용했다.
- 실제 Desktop에서 첫 공 발사와 드레인 뒤 첫 슬롯 `소모`, 두 번째 슬롯 `선택` 전환을 확인했다.

- 증상: `.tres` 설정을 더블클릭하면 Inspector는 보이지만 `Stack underflow! (Engine Bug)`가 11,000건 이상 반복됐다.

- 해결: 기본 편집기 생성 중의 중첩 호출을 Godot 기본 경로로 넘기는 재진입 깊이 가드를 추가했다.
- 실제 GUI 재검증: 진행 설정·보드 시점·범퍼·공 물리·발사 설정 5종에서 한국어 표시 5/5와 신규 오류 0건을 확인했다. 발사 설정 복제본의 `기본 발사 세기`를 0.7로 저장한 뒤 다른 설정을 열고 다시 열어 값 유지와 원본 무변경을 확인했으며 복제본은 제거했다.
- 자동·독립 재검증: 대표 5종 영문 저장 키·값 재열기 5/5, 한국어 표시명 직렬화 0건, 전체 자동 검사 15/15, Godot 4.7.1 스캔·Desktop 부팅 종료 코드 0, 독립 QA 통과. Web 검증은 정책에 따라 미실행했다.

- 증상: `direction_keys` 조준에서 방향키를 길게 눌러도 최초 한 단계만 각도·세기에 반영됐다.
- 재현: 방향키 조준으로 들어가 왼쪽·오른쪽 또는 위·아래 방향키를 누르고 유지한다.

- 해결: 방향키 조준 상태의 네 방향키 반복만 조준 명령으로 허용하고 `Space`, 공 선택, 플리퍼 선택 반복과 키 해제는 계속 차단했다.

- 해결: 실제 플레이 화면은 진행 버튼을 제공하지 않게 유지하고, 진행 도메인 회귀 테스트만 중립 진행 신호를 주입하도록 바꿨다.

## 사용자 기획·개발 변경으로 개선된 점

- 사용자가 발사 세기를 숫자뿐 아니라 보드 위 경로에서도 직관적으로 읽을 수 있도록 요청해, 조준선 길이와 텍스트가 최소·최대 속도와 선택 공의 속도 제한을 반영한 실제 예상 속도에 맞춰 함께 변하도록 보완했다.
- 사용자가 방향키 조준과 마우스 조준을 선택 가능하게 요청해 입력 장치를 물리 명령에서 분리했다. 따라서 같은 방향·세기는 조준 방식과 관계없이 같은 발사 명령과 초기 속도를 만든다.
- 사용자가 실제 조작에서 방향키 길게 누르기가 반영되지 않는 점을 발견해, 방향키 조준만 반복 입력을 허용하면서 `Space` 중복 방지 규칙은 유지하도록 개선했다.
- 내부 영문 속성명과 기획자용 한국어 표시 이름을 분리해 자동화·코드 호환성과 비개발자 편집성을 함께 유지했다.
- 공 슬롯, 공 원형, 보드 설계도, 웨이브 배치와 실제 공 인스턴스를 분리해 공이 보드 설정에 저장되지 않는 규칙을 지켰다.
- 사용자가 승인한 병렬 방식에 따라 계약, 보드 편집 도구, 웨이브 데이터, 2D 물리를 분리 구현하고 메인 작업자가 입력·화면·회귀를 통합했다.

## 5단계 플리퍼 선택·작동·공 패링

### 구현 결과

- 웨이브 배치에 방향키 하나로 조작할 `플리퍼 조작 대상`을 추가했다. 기획자는 `왼쪽만`, `오른쪽만`, `좌우 쌍` 중 하나를 고르고 해당 플리퍼 배치 지점을 연결한다.
- 기본·현재 웨이브는 하단의 좌우 플리퍼 두 개를 하나의 `좌우 쌍`으로 묶었다. 두 지점의 중점이 보드 아래쪽에 있으므로 아래 방향키로 선택하고 Space 한 번으로 함께 작동한다.
- 차원 독립 `플리퍼 작동 명령`과 물리 어댑터 경계를 만들었다. 현재는 2D 플리퍼만 연결하지만 미래 3D 물리 어댑터도 같은 방향키·발사·조작 대상 계약을 소비할 수 있다.
- 2D 플리퍼는 `대기 → 작동 → 유지 → 자동 복귀` 순서로 움직이고, 왼쪽과 오른쪽 역할은 서로 거울 방향으로 회전한다.
- 공 패링 시간 안의 첫 접촉에는 설정된 추가 힘을 한 번 적용한다. 좌우 쌍도 한 번의 Space 작동 전체에서 추가 힘은 최대 한 번이며, 표준 공의 최대 속도를 넘지 않게 제한한다.
- 표준·소형 플리퍼 원형에 각각 작동 설정을 연결했다. 현재 2D 디자인 연결표의 색도 실제 물리 플리퍼에 반영된다.
- Godot 인스펙터에서 내부 영문 저장 이름은 유지하면서 `플리퍼 조작 대상`, `작동 방식`, `올라가는 시간`, `돌아오는 시간`, `공 패링 시간` 등 한국어 이름·설명·단위를 표시하는 공용 표를 확장했다.
- 플레이 화면의 `PlayableBoard2D`에는 `시험할 웨이브 배치` 항목을 추가해, 기본 파일을 바꾸지 않고 기획자가 만든 웨이브 배치 복제본을 바로 연결해 실행할 수 있게 했다.
- 사용자 피드백에 따라 최초 플리퍼 조작 대상을 `아래 → 왼쪽 → 오른쪽 → 위` 순서로 자동 선택하고, 발사·낙하와 잘못된 방향 입력 뒤에도 선택이 비지 않도록 보완했다.

## 6단계 충돌·타입별 범퍼

### 구현 결과

- 범퍼 원형에 `충돌 반지름`, `타격당 내구도 감소`, `기본 점수 근거`, `복구 대기`, `복구 예고`, `안전 복구 여백`과 종류별 반응 설정을 추가했다. 내부 저장 이름은 영문을 유지하고 인스펙터에는 기획 용어와 한국어 설명을 표시한다.
- `일반 범퍼`, `반동 범퍼`, `경로 범퍼`, `발사 범퍼` 네 종류를 만들었다. 일반은 기본 반사, 반동은 속도 1.2배 후보값을 공 상한 안에서 적용하고, 경로는 지정한 지점을 순서대로 통과한 뒤 물리로 복귀하며, 발사는 지정 목표를 향해 자동으로 보낸다.
- `접촉 → 타격 → 분리`를 구분해 공이 붙어 있는 동안에는 내구도가 한 번만 줄고, 완전히 떨어졌다 다시 닿아야 새 타격이 된다.
- 내구도 0인 범퍼는 즉시 충돌을 끄고 기본 4초를 기다린다. 공이 겹치거나 곧 지나갈 예상 경로이면 복구를 미루며, 안전할 때 기본 0.75초 예고 후 최대 내구도로 돌아온다. 새 발사 준비에서는 모든 범퍼를 초기화한다.
- 보드 제작 도구에 마우스로 옮기는 `경로 지점`과 `발사 목표 지점`을 추가했다. 경로는 파란 점선과 순서 번호, 목표는 주황 선으로 보이며 실제 연결 순서는 웨이브 배치표가 저장한다.
- 논리 타격 결과에는 접촉 위치·방향·속도·충돌 세기·내구도 전후·기본 점수 근거를 담았다. 점수와 콤보 계산은 7단계가 이 결과를 소비하도록 분리했다.
- 현재는 2D 물리 어댑터가 실제 공과 범퍼를 움직인다. 미래 3D 어댑터는 같은 차원 독립 타격 요청·결과를 사용하고 충돌 검사와 물리 적용만 교체한다.

## 7단계 스코어·콤보·목표·실패

### 구현 결과

- 범퍼의 `기본 점수 근거`를 실제 스코어로 연결했다. 최종 증가량은 `기본 점수 × 콤보 배수`를 정수로 반올림한다.
- 기본 목업은 콤보 시간 2초, 타격당 배수 +0.5, 최대 5배다. `default_score_config.tres`를 복제하면 코드 수정 없이 조정할 수 있다.
- 기본 목표는 1,000점이며 `default_score_objective.tres` 복제본에서 웨이브별로 바꿀 수 있다.
- 목표를 먼저 달성해도 현재 공과 플리퍼 조작을 유지하며 추가 스코어를 얻는다. 공이 낙하한 뒤에만 클리어·다음 공 선택·스테이지 실패 중 하나를 확정한다.
- 플레이 HUD에 현재 스코어, 목표 스코어, 남은 목표, 콤보 수와 스코어 배수를 추가했다.

### 발견·수정한 문제

- 독립 QA에서 다음 공이 이미 진행 중일 때 이전 발사의 지연 타격이 들어오면 스코어가 바뀔 수 있는 결함을 발견했다. 활성 발사 ID가 일치하는 타격만 반영하도록 수정하고 실제 다음 공 진행 상태의 회귀 검사를 추가했다.
- 잘못된 스코어 설정으로 재설정한 뒤 이전 유효 설정이 남는 위험을 제거하고, 콤보 시간이 끝나면 HUD가 0콤보·1배로 돌아가도록 보완했다.
