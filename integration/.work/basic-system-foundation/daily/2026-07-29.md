# 2026-07-29 작업 기록

- 작업 ID: `basic-system-foundation` 3B 후속 보완 및 4단계 공 선택·조준·발사·반복
- 담당 역할: 메인 구현·서브 에이전트 병렬 구현·독립 교차 QA
- 환경과 기준 커밋: `feature/core-system`, `ac2d5e5` 기반 미커밋 작업 트리; macOS Apple M1; Godot `4.7.1.stable.official.a13da4feb`; Desktop Compatibility

## 구현 내용

- 보드 ID로 `stages/boards/content/<board_id>/` 아래 보드 설계도와 웨이브 배치표를 함께 복제하고 기존 경로 충돌을 거부하는 저장 규칙을 추가했다.
- `BoardAuthoring2D` 루트 변형을 항등값으로 바꾸고 단독 실행에서만 화면 중앙에 놓아, 씬 인스턴스 루트 변형 경고 없이 재사용하게 했다.
- 영문 GDScript·`.tres` 속성명을 유지하면서 Godot 기본 속성 편집기에 한국어 이름·설명·단위를 붙이는 공용 인스펙터 표시 계층을 추가했다.
- 표준 공 원형과 차원 독립 물리 설정, 웨이브 공 슬롯 1~3개, 조준 설정, 발사 명령·계산 결과, 발사 생명주기와 종료 결과를 구현했다.
- `direction_keys`와 `mouse` 두 조준 방식을 `.tres` 하나로 교체하고 두 방식 모두 `Space`로 발사하게 했다.
- 현재 2D용 `RigidBody2D` 어댑터를 구현하고, 차원 독립 보드 좌표·속도를 현재 2D 물리 좌표로 바꾸는 변환을 조립 계층에서 주입했다. 미래 3D 어댑터는 같은 명령·결과 계약을 소비할 수 있다.
- 실제 웨이브 화면에 공 선택→조준→발사→드레인 또는 보드 밖 종료→다음 공 선택 반복을 연결했다. 가져온 공을 모두 사용해도 4단계에서는 스코어 성공·실패를 판단하지 않는다.
- 공 진행 중 방향키는 상대 위치에 따라 고유 배정된 플리퍼 선택, `Space`는 플리퍼 작동 요청으로 라우팅했다. 실제 움직임은 5단계 범위로 남겼다.

## 구현 결과

- 기본 목업 웨이브는 독립 슬롯 `ball_slot_1~3`에 표준 공 세 개를 제공하며 1~3개 목록만 유효하다.
- 숫자키와 네 방향키로 남은 공을 선택하고 첫 `Space`는 선택 확정, 두 번째 `Space`는 발사, 공 진행 중 `Space`는 플리퍼 요청 하나만 만든다. 방향키 조준에서는 방향키를 길게 누르는 동안 각도·세기가 반복 조절된다.
- 마우스 조준은 58°로 투영된 화면 위치를 보드 평면으로 역변환해 방향·세기를 만들며, 방향키 조준은 입력 한 번당 승인된 각도·세기 변화량을 사용한다.
- 활성 공은 0개 또는 1개이며 고속 이동용 연속 충돌 검사, 최대 직선·회전 속도 제한과 보드 밖 안전 종료를 적용했다.
- 실제 Desktop에서 첫 공 발사와 드레인 뒤 첫 슬롯 `소모`, 두 번째 슬롯 `선택` 전환을 확인했다.

## 트러블슈팅

- 증상: `.tres` 설정을 더블클릭하면 Inspector는 보이지만 `Stack underflow! (Engine Bug)`가 11,000건 이상 반복됐다.
- 재현: Godot 4.7.1에서 `default_launch_config.tres`를 더블클릭해 출력 오류 11,275건을 확인했다.
- 원인: 한국어 Inspector 플러그인의 `_parse_property()`가 기본 속성 편집기를 만드는 과정에서 다시 호출돼 재귀가 발생했다.
- 추적: NAN AI 해커톤 프로젝트의 `(개발 주) 핵심 코어 루프 구현` 스프린트에 `KAN-104` 버그로 생성했다.
- 해결: 기본 편집기 생성 중의 중첩 호출을 Godot 기본 경로로 넘기는 재진입 깊이 가드를 추가했다.
- 실제 GUI 재검증: 진행 설정·보드 시점·범퍼·공 물리·발사 설정 5종에서 한국어 표시 5/5와 신규 오류 0건을 확인했다. 발사 설정 복제본의 `기본 발사 세기`를 0.7로 저장한 뒤 다른 설정을 열고 다시 열어 값 유지와 원본 무변경을 확인했으며 복제본은 제거했다.
- 자동·독립 재검증: 대표 5종 영문 저장 키·값 재열기 5/5, 한국어 표시명 직렬화 0건, 전체 자동 검사 15/15, Godot 4.7.1 스캔·Desktop 부팅 종료 코드 0, 독립 QA 통과. Web 검증은 정책에 따라 미실행했다.

- 증상: `direction_keys` 조준에서 방향키를 길게 눌러도 최초 한 단계만 각도·세기에 반영됐다.
- 재현: 방향키 조준으로 들어가 왼쪽·오른쪽 또는 위·아래 방향키를 누르고 유지한다.
- 원인: `Space` 중복 발사를 막기 위해 키 반복 `echo`를 입력 라우터 입구에서 전부 거부했다.
- 해결: 방향키 조준 상태의 네 방향키 반복만 조준 명령으로 허용하고 `Space`, 공 선택, 플리퍼 선택 반복과 키 해제는 계속 차단했다.
- 재검증: 오른쪽 반복 2회는 `2° × 2`, 위 반복 1회는 세기 `0.05 × 1`을 누적했다. `Space` 반복 발사 0회, 관련 검사 3종과 전체 검사 15종이 모두 통과했다.

- 증상: 기존 진행 통합 검사가 웨이브 화면을 `NavigableScreen`과 임시 진행 버튼으로 가정해 실패했다.
- 재현: 새 실제 웨이브 화면에서 `PROGRESSION_NAVIGATION_SMOKE` 실행.
- 원인: 4단계에서 `Space`와 충돌하던 임시 **웨이브 클리어 처리** 버튼을 제거했지만 테스트가 이전 목업 UI를 직접 눌렀다.
- 해결: 실제 플레이 화면은 진행 버튼을 제공하지 않게 유지하고, 진행 도메인 회귀 테스트만 중립 진행 신호를 주입하도록 바꿨다.
- 재검증: `PROGRESSION_NAVIGATION_SMOKE: PASS`.

- 증상: 기존 보드 회귀 두 개가 범퍼 5개와 이전 고정 외곽선 투영 수치를 기대해 실패했다.
- 재현: 현재 기준 커밋의 기본 보드는 이미 범퍼 9개와 수정된 외곽선을 사용한다.
- 원인: 테스트 기대값이 현재 커밋된 기본 보드 데이터보다 오래됐다.
- 해결: 현재 승인 데이터의 범퍼 9개를 확인하고, 커스텀 복제 검사는 고정 개수 대신 원본 대비 `+1`, 시점 검사는 투영·역투영과 각도 변화 관계를 검증하도록 바꿨다.
- 재검증: `BOARD_LAYOUT_CONFIG_SMOKE: PASS`, `BOARD_MOCKUP_2D_ASSEMBLY_SMOKE: PASS`.

- 증상: macOS 기본 창 캡처가 Metal 렌더 면을 검게 저장하는 경우가 있었다.
- 원인: 일반 창 캡처와 Godot Metal 표면 합성 시점 차이였다.
- 해결: Godot 앱 상태를 직접 캡처하고 PNG로 변환해 동일 상태를 다시 확인했다.
- 재검증: 공 선택·마우스 조준·공 진행·다음 공 선택 4장에 보드와 HUD가 함께 표시됐다.

## 사용자 기획·개발 변경으로 개선된 점

- 사용자가 발사 세기를 숫자뿐 아니라 보드 위 경로에서도 직관적으로 읽을 수 있도록 요청해, 조준선 길이가 현재 발사 세기에 비례해 변하도록 보완했다.
- 사용자가 방향키 조준과 마우스 조준을 선택 가능하게 요청해 입력 장치를 물리 명령에서 분리했다. 따라서 같은 방향·세기는 조준 방식과 관계없이 같은 발사 명령과 초기 속도를 만든다.
- 사용자가 실제 조작에서 방향키 길게 누르기가 반영되지 않는 점을 발견해, 방향키 조준만 반복 입력을 허용하면서 `Space` 중복 방지 규칙은 유지하도록 개선했다.
- 내부 영문 속성명과 기획자용 한국어 표시 이름을 분리해 자동화·코드 호환성과 비개발자 편집성을 함께 유지했다.
- 공 슬롯, 공 원형, 보드 설계도, 웨이브 배치와 실제 공 인스턴스를 분리해 공이 보드 설정에 저장되지 않는 규칙을 지켰다.
- 사용자가 승인한 병렬 방식에 따라 계약, 보드 편집 도구, 웨이브 데이터, 2D 물리를 분리 구현하고 메인 작업자가 입력·화면·회귀를 통합했다.

## 남은 작업과 위험

- 실제 플리퍼 움직임·복귀·패링은 5단계까지 `미검증`이다.
- 범퍼·벽·일반 오브젝트는 현재 시각 원형이며 실제 충돌·내구도·점수는 6~8단계까지 `미검증`이다.
- 목표 스코어를 넘긴 뒤 현재 공 낙하까지 계속 플레이하고 최종 스코어로 성공·실패를 판단하는 흐름은 7단계까지 `미검증`이다.
- 다양한 보드 외곽선에서의 장시간 터널링·끼임·무한 반복·경로별 성공률과 FPS·메모리는 `미측정`이다.
- 허용 최대 속도의 10배인 비정상 강제 속도에서는 한 물리 틱에 레일을 통과할 수 있었다. 실제 설정 허용 범위에서는 재현되지 않았으며, 6단계 범퍼 힘·고속 충돌 QA에서 다시 확인한다.
- 한국어 인스펙터는 대표 설정 5종 실제 열기와 복제본 값 변경·저장·재열기를 확인했으며, 모든 설명 말풍선을 일일이 띄우는 수동 검증만 남아 있다.
- 3D `RigidBody3D` 어댑터는 최종 그래픽 방향 결정 뒤 구현하며 현재는 계약 경계만 검증했다.
