# 2026-07-27 작업 기록

- 작업 ID: `basic-system-foundation` 1단계
- 담당 역할: 구현
- 환경과 기준 커밋: Windows PowerShell, 저장소 작업 트리, 로컬 Godot `4.6.stable.official.89cea1439`; 프로젝트·CI 기준 Godot 4.7/4.7.1

## 구현 내용

- `DECISIONS.md`와 `app/SPEC.md`에 3D 런타임, 차원 독립 도메인 경계와 최상위 화면 전환 계약을 먼저 기록했다.
- `AppRoot`와 단일 `ScreenNavigator`를 추가하고, 화면 경로를 `NavigationConfig` 리소스 한 곳에서 조립했다.
- 메인 로비·스테이지 선택·보상·결과는 `Control`, 웨이브·보스는 `Node3D` 루트의 독립 씬으로 분리했다.
- 임시 순환 버튼은 화면 분리 검증 의도만 발행하며, 실제 진행 규칙은 소유하지 않게 했다.
- `project.godot`의 메인 씬을 앱 루트로 교체했다.
- Web 프리셋을 실행 가능 상태로 명시하고 `integration/**`, `.agents/**`, `**/.work/**`를 빌드 리소스에서 제외했다.
- 런타임 전환 스모크와 편집기 리소스 검사용 GDScript를 추가했다.

## 구현 결과

- 6개 화면 식별자와 `PackedScene` 경로가 중앙 설정에 각각 한 번씩 등록됐다.
- 내비게이터는 미등록 화면, 현재 화면 재요청과 전환 중 요청을 거부하고 활성 화면 하나만 소유하도록 구현했다.
- 기존 `example_2d.tscn`의 사용자 문구 변경은 수정하지 않았다.
- 2단계 진행 도메인, 물리, 보상 규칙과 Git 작업은 수행하지 않았다.

## 트러블슈팅

- 증상: 로컬 Godot 4.6 헤드리스 런타임이 앱 루트 실행 시 signal 11로 종료됐다.
- 재현: `D:\Godot\Godot_v4.6-stable_win64_console.exe --headless --path . --quit-after 2`
- 원인: 같은 명령으로 변경하지 않은 `res://example_2d.tscn`을 직접 실행해도 signal 11이 발생했다. 프로젝트 기준 4.7과 로컬 4.6의 버전 차이 또는 현재 헤드리스 환경 문제로 좁혔으나 정확한 원인은 미확정이다.
- 해결: 로컬 4.6 결과를 보조 증거로만 분리하고, 개별 씬 편집기 로드와 정적 검사를 수행했다.
- 재검증: 앱 루트와 6개 화면의 편집기 로드는 7/7 성공했다. 전환 런타임은 4.7.1 환경에서 재검증해야 한다.

- 증상: Web 시험 내보내기가 시작되지 않았다.
- 재현: `D:\Godot\Godot_v4.6-stable_win64_console.exe --headless --path . --export-release Web <임시 index.html>`
- 원인: 로컬 Godot 4.6의 `web_nothreads_debug.zip`과 `web_nothreads_release.zip` 내보내기 템플릿이 설치되지 않았다.
- 해결: 외부 다운로드나 프로젝트 물리 설정 변경은 승인 범위를 벗어나 수행하지 않았다.
- 재검증: Web 프리셋의 이름, `runnable=true`와 제외 필터는 정적으로 통과했다. 실제 산출물은 4.7.1 Web 템플릿 환경에서 재검증해야 한다.
