# 애플리케이션 조립과 최상위 화면 전환 명세

- 기능: 앱 부트스트랩과 최상위 화면 전환
- 상태: approved
- 승인 기록: 2026-07-27 사용자가 마스터 계획과 1단계 구현 승인
- 관련 결정: `DEC-20260727-01`

## 목적과 사용자 경험

- 메인 로비, 스테이지 선택, 웨이브, 보상, 보스와 결과를 서로 독립된 씬으로 제공한다.
- 화면 전환 중 중복 생성과 이전 화면 잔존을 막고, 이후 진행 도메인이 같은 전환 진입점을 사용할 수 있게 한다.
- 최종 플레이 공간의 2D·3D 그래픽은 미확정으로 유지하고 현재 목업은 2D로 제공한다. 진행 규칙과 화면 식별자는 표현 노드 타입을 알지 않는다.

## 승인된 동작

| 화면 식별자 | 장면 역할 | 루트 타입 | 2단계 진행 요청 |
| --- | --- | --- | --- |
| `main_lobby` | 메인 로비 | `Control` | 런 시작 |
| `stage_selection` | 스테이지 선택 | `Control` | 현재 스테이지 시작 |
| `wave` | 일반 웨이브 플레이 공간 | `Node2D` 목업 | 웨이브 클리어 |
| `reward` | 보상 구매 화면 자리 | `Control` | 보상 완료 |
| `boss` | 보스 웨이브 플레이 공간 | `Node2D` 목업 | 보스 웨이브 클리어 |
| `results` | 스테이지·런 결과 화면 | `Control` | 결과 계속 진행 |

- 화면 버튼은 다음 화면 ID를 직접 요청하지 않고 진행 요청 ID를 발행한다. 실제 허용 순서와 분기는 `game_flow/`의 전환 결과가 결정한다.
- 앱 시작 시 경로 설정의 초기 화면을 정확히 한 번 연다.
- 한 시점에 화면 호스트가 소유하는 활성 최상위 화면은 하나다.
- 알 수 없는 화면, 현재 화면과 같은 대상, 전환 처리 중 추가 요청은 상태를 바꾸지 않고 거부한다.
- 전환할 때 이전 화면은 호스트에서 즉시 분리하고 안전하게 해제한 뒤 새 화면을 추가한다.
- 화면은 `progression_requested(action_id)` 의도만 발행하며 진행 모델, 내비게이터나 다른 화면을 직접 참조하지 않는다.

## 데이터와 상태

- `ScreenIds`: 표시 이름·장면 경로와 분리된 안정적인 화면 식별자의 단일 정의다.
- `ScreenRoute`: 화면 식별자와 `PackedScene` 참조 한 쌍이다.
- `NavigationConfig`: 초기 화면과 전체 경로 목록을 편집 가능한 `Resource`로 제공한다.
- `ScreenNavigator`: 현재 화면 식별자, 현재 화면 인스턴스와 전환 중 상태만 소유한다.
- `AppRoot`: 앱 시작, 진행 모델 조립과 진행 단계→화면 ID 변환만 담당한다. 런·스테이지·웨이브 규칙과 상태는 `game_flow/`가 소유한다.

## 공용 UI 글꼴

- 6개 화면의 기본 UI 글꼴은 프로젝트에 포함된 `Pretendard Regular`를 사용한다.
- 폰트와 배포 라이선스는 `ui/components/theme/fonts/`, 공용 Godot `Theme`은 `ui/components/theme/`이 소유한다.
- 앱 화면은 운영체제에 설치된 폰트에 의존하지 않고 같은 공용 `Theme` 리소스를 참조한다.
- 폰트 파일은 사용자가 지정한 눈누 Pretendard 페이지의 Regular Web 폰트를 사용하며, SIL Open Font License 1.1 전문을 폰트와 함께 보관한다.
- 이번 결정은 한국어 글리프 가독성 복구를 위한 기본 리소스 선택이다. 최종 타이포그래피, 다국어와 폰트 서브세팅은 후속 UI 범위다.

## 기능 경계와 제외 범위

- 메뉴·HUD의 최종 레이아웃과 아트는 `ui/`, 카메라·효과·음향은 `presentation/`이 소유한다.
- 웨이브 클리어, 보상 완료, 보스 완료, 실패와 리트라이 순서는 `game_flow/SPEC.md`와 진행 모델이 판단한다.
- 웨이브·보스의 공, 보드와 물리 기능은 현재 2D 목업 자리만 제공하며 실제 물리는 후속 단계에서 구현한다.
- 2D 목업과 미래 3D 표현은 같은 차원 독립 보드·진행 설정을 소비하는 별도 어댑터로 둔다.
- 오토로드, 저장, 비동기 로딩, 전환 애니메이션과 런타임 2D/3D 토글은 이번 단계에서 추가하지 않는다.

## 수용 기준

- 6개 화면 씬이 각각 독립적으로 파싱·인스턴스화된다.
- 앱 루트가 설정된 초기 화면 하나만 생성한다.
- 6개 화면을 반복 순회해도 화면 호스트의 자식 수는 항상 1이다.
- 알 수 없는 화면과 현재 화면 재요청은 거부되고 현재 화면을 보존한다.
- 웨이브와 보스 화면은 현재 `Node2D` 목업, 나머지 화면은 `Control` 루트를 사용한다.
- 화면 경로는 코드 상수로 분산하지 않고 하나의 `NavigationConfig` 리소스에서 교체할 수 있다.
- 기능 디렉토리가 `app/`을 역참조하지 않고 앱 코드가 게임 진행 규칙을 소유하지 않는다.
- Godot 프로젝트 스캔, 자동 회귀와 Desktop 실행이 통과한다. 단계별 Web 빌드는 최종 Web QA 또는 사용자 명시 요청 전까지 생략한다.
- Desktop과 Web의 6개 화면에서 현재 한국어 제목·설명·버튼이 네모 글리프 없이 표시된다.
- 6개 화면의 기본 폰트는 공용 `Theme` 하나를 교체해 함께 변경할 수 있고 시스템 폰트에 의존하지 않는다.

## 미확정 사항

- 보상·코인·유물·패시브 유지 범위와 결과 화면의 최종 콘텐츠는 후속 단계에서 확정한다.
- 화면 전환 애니메이션, 로딩 화면과 뒤로 가기 정책은 후속 UI·내비게이션 계획 대상이다.
- 2D·3D 최종 표현 선택과 각 물리 어댑터의 Web 호환성은 후속 결정 및 최종 Web QA에서 검증한다.
