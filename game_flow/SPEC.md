# 진행 도메인 명세

- 기능: 런·스테이지·웨이브 진행 상태와 전환 결과
- 상태: approved
- 승인 기록: 2026-07-28 사용자가 1단계 커밋·푸시 후 2단계 구현을 승인함
- 관련 기준: `GAME_TERMS.md`, `GROUND_RULES.md` B·H, `D-01`

## 목적

- 런, 현재 스테이지, 현재 웨이브와 보상·보스 단계를 화면 및 물리 노드와 분리해 관리한다.
- 하나의 요청은 최대 한 번만 진행을 바꾸고, 중복·역행·알 수 없는 요청은 기존 상태를 보존한 채 거부한다.
- 앱에는 화면 ID가 아니라 승인 여부와 변경 전후 진행 단계가 담긴 전환 결과만 제공한다.

## 진행 계층

### 런

```text
대기
→ 스테이지 1
→ 스테이지 2
→ 스테이지 3
→ 런 결과
→ 대기
```

- 런 시작 시 현재 스테이지는 1이고 완료 목록은 비어 있다.
- 현재 스테이지 클리어만 완료 목록에 한 번 추가하고 다음 스테이지 준비로 진행한다.
- 스테이지 3 클리어 뒤에는 런 결과 상태가 된다.
- 현재 스테이지 실패와 리트라이는 이미 완료한 이전 스테이지 목록을 변경하지 않는다.

### 스테이지

```text
준비
→ 일반 웨이브 1 → 보상
→ 일반 웨이브 2 → 보상
→ 일반 웨이브 N → 보상
→ 보스 웨이브
→ 스테이지 결과
```

- 일반 웨이브 클리어만 보상 단계로 진행한다.
- 설정된 마지막 웨이브 이전의 보상 완료는 다음 일반 웨이브를 시작한다.
- 설정된 마지막 일반 웨이브의 보상 완료만 보스 웨이브를 시작한다.
- 활성 일반·보스 웨이브의 실패 결과는 스테이지 실패를 확정한다.
- 실패 결과 화면의 계속 요청은 같은 스테이지의 일반 웨이브 1부터 리트라이한다.
- 클리어 결과 화면의 계속 요청은 다음 스테이지 준비로 진행한다.

### 웨이브

- 웨이브는 `준비 → 플레이 중 → 클리어 또는 실패` 순서로만 진행한다.
- 플레이 중에 받은 첫 유효 결과만 확정한다.
- 종료된 웨이브의 중복 결과와 준비 상태의 결과는 거부한다.
- 점수, 공 수량과 마지막 공 판정은 후속 핀볼·스테이지 기능이 계산하고 이 단계에서는 `클리어` 또는 `실패` 결과만 소비한다.

## 공개 요청과 결과

| 요청 | 허용 상태 | 성공 후 상태 |
| --- | --- | --- |
| `start_run` | 런 대기 | 스테이지 준비 |
| `start_stage` | 스테이지 준비 | 일반 웨이브 1 |
| `wave_cleared` | 일반·보스 웨이브 | 보상 또는 스테이지·런 결과 |
| `wave_failed` | 일반·보스 웨이브 | 스테이지 실패 결과 |
| `reward_completed` | 보상 | 다음 일반 웨이브 또는 보스 웨이브 |
| `continue_from_result` | 스테이지·런 결과 | 리트라이, 다음 스테이지 준비 또는 런 대기 |

- `ProgressionTransitionResult`는 승인 여부, 요청 ID, 변경 전후 단계, 거부 이유와 상태 스냅샷을 제공한다.
- 상태 스냅샷은 현재 스테이지 번호, 현재 일반 웨이브 번호, 스테이지 결과와 완료 스테이지 번호를 포함한다.
- 거부 결과는 진행 상태와 완료 목록을 변경하지 않는다.
- `ProgressionConfig` Resource가 스테이지 수와 스테이지당 일반 웨이브 수를 제공하며 기본 `.tres` 값은 각각 3이다.

## 앱 연결

| 진행 단계 | 앱 화면 |
| --- | --- |
| 런 대기 | 메인 로비 |
| 스테이지 준비 | 스테이지 선택 |
| 일반 웨이브 | 웨이브 |
| 보상 | 보상 |
| 보스 웨이브 | 보스 |
| 스테이지 결과·런 결과 | 결과 |

- 화면은 다음 화면 ID 대신 진행 요청 ID만 발행한다.
- `AppRoot`는 진행 요청을 `GameProgression`에 전달하고 승인된 결과의 단계만 `ScreenIds`로 변환한다.
- `game_flow/`는 `app/`, `ui/`, 씬 경로와 `Node2D`·`Node3D` 타입을 참조하지 않는다.

## 제외 범위와 미확정 정책

- 목표 스코어, 공 라이프, 보상 구매, 코인, 유물, 보스 전투와 화면 표시 데이터는 구현하지 않는다.
- D-02~D-09의 공 수량, 초기화, 재화·보상·유물 유지와 영구 해금 정책을 확정하지 않는다.
- 스테이지 1→2→3의 구조적 진행만 기록하며 스테이지 클리어 보상이나 영구 개방 데이터를 만들지 않는다.
- 실제 마지막 공 결과의 동시 클리어·실패 경계는 결과 생산 기능이 추가되는 단계에서 검증한다.

## 수용 기준

1. 기본 설정의 런이 스테이지 1→2→3 순서를 지키며 각 스테이지에 일반 웨이브와 보상이 정확히 3회씩 발생한다.
2. 커스텀 `.tres`의 스테이지 수와 일반 웨이브 수가 진행 순서와 보스 진입 시점에 반영된다.
3. 설정된 마지막 보상 전에는 보스 웨이브, 보스 클리어 전에는 스테이지 클리어가 발생하지 않는다.
4. 중복 완료·실패, 잘못된 단계와 알 수 없는 요청이 거부되고 상태가 보존된다.
5. 실패 후 같은 스테이지의 일반 웨이브 1로 돌아가며 이전 완료 스테이지가 보존된다.
6. 화면 버튼으로 전체 정상 흐름을 진행했을 때 진행 단계와 활성 화면이 일치하고 활성 화면은 하나다.
7. `game_flow/`에 화면 식별자, 씬 경로 또는 물리 노드 참조가 없다.
8. 기존 화면 직접 전환 API의 경계 검증과 Godot 4.7.1 Desktop 실행이 회귀하지 않는다.
