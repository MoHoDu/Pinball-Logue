## 조사 기준과 통합 아트 방향

- 로컬 승인 기준을 우선해 상단이 좁고 하단이 넓은 `58°` 경사 원근과 16:9 한 화면 구도를 사용한다.
- 한 줄 방향은 `어두운 밀실 한가운데, 미친 발명가가 용접한 거대한 처형용 핀볼 기계`로 통일한다.
- 주조색은 검정·짙은 갈색·녹슨 철색, 재질은 녹슨 주철·그을린 목재·변색 황동·기름때·노출 전선·용접 자국을 사용한다.
- 강조색은 충돌과 약점을 위한 따뜻한 주황, 바운스·전기 기능을 위한 제한적 옅은 청색으로 나눈다.
- 일반 범퍼는 스프링식 원형 톱날 허브, 플리퍼는 톱니가 있는 곰덫 턱, 보스는 보드에 결합된 대형 AI 제어 코어와 명확한 약점 실루엣으로 만든다.
- 장식과 VFX보다 공·플리퍼·범퍼·보스 약점과 안전·고득점·보스 공격 경로의 가독성을 우선한다.
- 밝은 장난감 핀볼, 과도한 네온, 화면을 덮는 파티클, 코스믹 유기체 중심 디자인은 사용하지 않는다.
- 살점, 내장, 핏자국처럼 화면 자체를 지저분하게 만드는 고어 표현은 오브젝트와 보드 원화에 넣지 않는다.
- 피·불꽃·스파크가 필요한 타격감은 기본 아트에 굳히지 않고, 공과 경로를 가리지 않는 별도 순간 연출 레이어로만 다룬다.

## 조립 기준

- 보드 목업은 현재 기본 데이터와 맞춰 범퍼 5개, 플리퍼 2개, 발사 지점 1개, 드레인 1개와 유물 슬롯 3개를 수용한다.
- 일반 범퍼 4개와 바운스 범퍼 1개를 사용해 기능 차이가 실루엣과 색으로 즉시 읽히게 한다.
- 보스는 상단 중앙에 배치하고 약점으로 이어지는 중앙 공격 경로와 좌우 점수 경로를 시각적으로 분리한다.
- 기본 공은 활성 공 1개 규칙에 맞춘 무광 금속 표준 시험구이며, 최대 속도에서도 배경과 구분되도록 밝은 테두리와 작은 주황 식별점을 사용한다.
- 보드와 개별 오브젝트는 3D 렌더처럼 보이는 사실적 입체 모델링을 피하고, 평면 도형·굵고 정돈된 외곽선·2~3단계 셀 명암·최소 그림자를 사용하는 명확한 2D 게임 아트로 생성한다.
- 58° 투영은 보드 전체의 사다리꼴 구도와 오브젝트 상단면 방향에만 적용하고, 오브젝트의 높이·부피를 과장하지 않는다.
- 개별 오브젝트는 프로젝트 적용을 위해 평면 마젠타 크로마키 원본을 생성한 뒤 로컬에서 알파 PNG로 변환한다.

## 생성 방식과 반복 규칙

- 기본 내장 `image_gen`을 사용한다.
- 각 단계는 `stylized-concept` 분류의 게임 아트로 생성한다.
- 1단계 보드 목업을 이후 모든 개별 오브젝트의 시각 기준 이미지로 사용한다.
- 개별 오브젝트는 평면 `#ff00ff` 배경, 그림자·반사·바닥면 없는 단일 피사체로 생성하고 설치된 크로마키 제거 도구로 알파 PNG를 만든다.
- 각 단계는 첫 결과 검수 후 한 번에 한 가지 수정만 반영한다.
- 사용자 피드백과 단계 승인을 받은 뒤 다음 단계로 이동한다.
- 기존 파일은 덮어쓰지 않고 단계·버전이 드러나는 파일명을 사용한다.

## 최종 검증 흐름

1. 보드 목업과 개별 오브젝트를 나란히 비교해 원근, 광원 방향, 팔레트와 마모 표현을 대조한다.
2. 개별 알파 PNG의 알파 채널, 투명 모서리, 피사체 점유율과 색 번짐을 검사한다.
3. 각 이미지를 128px 미리보기로 축소해 실루엣과 기능 구분을 확인한다.
4. 최종 조립 이미지에서 공, 플리퍼, 일반·바운스 범퍼, 보스 약점과 주요 경로의 가독성을 확인한다.
5. 생성 프롬프트, 사용 방식, 출력 경로와 선정·수정 이유를 보고한다.

## 미확정 사항과 가정

- 바운스 범퍼 세부형은 정적 아트에서도 기능이 가장 명확한 `부스터형`을 우선 후보로 가정한다. 거울형·패링형으로 바꾸려면 3단계 전에 사용자 승인을 받는다.
- 보스의 확정 세부 기획은 로컬 문서에 아직 없으므로 `스테이지 1 AI 외부 피막·톱날 제어 코어`를 아트 탐색 후보로만 사용한다.
- 개별 오브젝트의 실제 충돌 영역, 축 위치, 픽셀 크기와 애니메이션 프레임은 후속 Godot 적용 계획에서 확정한다.
- 생성 이미지는 MVP 아트 후보이며 자동으로 최종 확정 또는 코드 적용 상태가 되지 않는다.
- 이미지 파일의 Git 포함 여부와 Confluence 등록은 생성·검토 후 별도 승인 대상이다.

## 중단 조건

- 결과가 58° 보드 투영과 현저히 다르거나 공·경로 가독성을 해치면 다음 단계로 진행하지 않는다.
- 개별 오브젝트가 보드 목업과 같은 제품군으로 보이지 않으면 해당 단계에서 한 가지 수정만 적용해 재생성한다.
- 크로마키 제거 후 마젠타 잔상·형태 손실이 남으면 재시도하고, 그래도 실패하면 true transparency CLI 전환 여부를 사용자에게 묻는다.
- 보스 세부 방향이 현재 후보와 다르다는 피드백이 오면 5단계 전에 계획과 프롬프트를 수정한다.
