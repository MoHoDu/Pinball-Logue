## 통합 비주얼 방향

- 최종 표현은 전부 `Node2D`와 2D 래스터 스프라이트로 만든다. 3D 노드, 3D 물리와 런타임 2D/3D 전환은 사용하지 않는다.
- 특정 게임의 고유 에셋을 복제하지 않고, 다음 일반 특성만 결합한다: 각진 저폴리 면, 작은 텍스처가 확대된 듯한 거친 표면, 제한된 명암 단계, 하드 에지 그림자, 디더와 필름 그레인, 어두운 저채도 팔레트.
- 재질은 검게 산화된 철, 녹슨 주철, 변색 황동, 그을린 목재와 기름때를 사용한다.
- 조명은 상단의 따뜻한 텅스텐 1개를 기본으로 하고, 범퍼 활성 표시는 약한 주황, 전기 장식은 제한적인 청색만 사용한다.
- 공, 플리퍼 타격면, 범퍼 실루엣과 드레인 입구는 배경 장식보다 높은 명도 대비를 가진다.
- 보드 시점은 숫자 각도로 새로 확정하지 않고 이미지 1의 화면상 사다리꼴 비율을 기준으로 조정 가능한 2D 투영값으로 저장한다.

## 보드와 게임 범위

- 16:9 고정 화면에서 보드는 왼쪽 약 65~70%, 비기능성 세로 패널은 오른쪽 약 30~35%를 차지한다.
- 보드에는 외곽 레일, 우측 자동 투입 레인, 상단·중단 범퍼 5개, 하단 플리퍼 2개, 중앙 드레인 1개만 실제 게임 요소로 둔다.
- 시작 시 공 1개를 우측 레인에서 자동 투입한다. 별도 발사 조작과 플런저 기능은 만들지 않는다.
- 왼쪽 플리퍼는 `A` 또는 `←`, 오른쪽 플리퍼는 `D` 또는 `→`를 누르는 동안 작동하고 놓으면 복귀하는 직접 조작안을 사용한다.
- 드레인에 들어간 공은 결과를 한 번만 발생시키고 짧은 대기 뒤 같은 공 한 개를 다시 자동 투입한다. 라이프, 실패와 게임 오버는 만들지 않는다.
- 범퍼는 공을 바깥 방향으로 반사하고 짧은 크기·밝기 피드백만 재생한다. 점수, 내구도, 파괴와 복구는 이 프로토타입에서 사용하지 않는다.
- 공은 중력, 반발, 마찰, 감쇠와 최대 속도를 설정값으로 가지며 연속 충돌 검사를 켠다.

| 리소스 | 형식과 역할 | 애니메이션 구조 |
| --- | --- | --- |
| 보드 바닥 | 1920×1080 불투명 PNG, 플레이필드·우측 패널·고정 장식 | 없음 |
| 전경 레일 오버레이 | 1920×1080 알파 PNG, 공보다 앞에 보여야 하는 하단·측면 레일 | 없음 |
| 범퍼 | 알파 PNG 1종을 5곳에 재사용 | 별도 프레임 없이 Godot에서 짧은 `scale`·색 밝기 변화 |
| 플리퍼 | 왼쪽 회전축이 명확한 알파 PNG 1종, 오른쪽은 수평 반전 | 별도 프레임 없이 Godot에서 피벗 기준 `rotation` |
| 공 | 작은 알파 PNG 1종 | `RigidBody2D` 이동·회전만 사용 |
| 드레인 | 보드 바닥에 통합된 입구와 필요 시 알파 전경 프레임 | 애니메이션 없음, 감지는 `Area2D` |

- 모든 생성물은 `Resources/Art/xp_low_poly_pinball/` 아래에 버전 파일명으로 저장하고 기존 `output/imagegen/mvp-wave-industrial-horror/`와 `Resources/Art/flipper_demo_v002/`를 덮어쓰지 않는다.
- 원본 프롬프트, 생성 방식, 수정 횟수와 선정 이유를 작업 일자 기록에 남긴다.

## 최종 검증 흐름

1. 고정 시드와 같은 초기 투입 속도로 60초 플레이를 반복해 활성 공 수, 범퍼 접촉과 드레인 횟수를 기록한다.
2. 최대 허용 속도와 다섯 입사각에서 범퍼 관통·반동 방향·속도 상한을 검사한다.
3. 좌우 플리퍼를 단독·동시·연타해 잘못된 작동, 복귀 불능, 공 관통과 중복 힘 적용을 확인한다.
4. 드레인 진입과 보드 밖 이탈이 한 공당 한 번만 처리되고 재생성 사이 활성 공이 둘이 되지 않는지 확인한다.
5. 1280×720과 1920×1080 캡처에서 XP형 보드 구도, 동일 아트 스타일, 공·범퍼·플리퍼·드레인의 가독성을 대조한다.
6. 기존 핵심 자동 검사를 다시 실행해 격리 프로토타입이 기존 씬을 깨뜨리지 않았는지 확인한다.

## 미확정 사항과 가정

- `게임은 네 요소만 구현`은 기존 시스템을 삭제하는 뜻이 아니라, 이번 실행 가능한 프로토타입 화면에서 공·플리퍼·범퍼·드레인 외 기능을 연결하지 않는 뜻으로 가정한다.
- 특정 작품명은 시각 특성을 설명하는 참고어일 뿐, 고유 캐릭터·UI·로고·소품을 복제하지 않는다.
- 보드 투영의 숫자 각도는 확정하지 않는다. 이미지 1과 화면상으로 맞는 조정 가능한 값만 사용한다.
- 플리퍼·공·범퍼 물리 수치는 기존 값도 확정값도 사용하지 않고, 별도 복제 설정의 조정 가능한 프로토타입 값으로 시작한다.
- D-01~D-09는 이 프로토타입에서 사용하거나 결정하지 않고 미결 상태를 유지한다.
- 우측 패널은 구도 유지용 비기능성 장식으로 시작한다.
- 기본 실행 장면 교체, Git 커밋·푸시, Jira·Confluence 갱신은 별도 사용자 승인 대상이다.

## 중단 조건

- 생성 결과가 사실적 PBR 3D 렌더처럼 보이거나 이미지 1의 보드 비율·장치 구역을 잃으면 리소스 분리로 진행하지 않는다.
- 공·범퍼·플리퍼의 광원·카메라·질감 밀도가 서로 다르면 Godot 연결 전에 해당 리소스만 수정한다.
- 기존 기능 파일의 대규모 삭제나 기본 실행 흐름 교체가 필요해지면 작업을 멈추고 사용자 승인을 다시 받는다.
- 터널링, 공 중복 생성, 드레인 중복 결과 또는 플리퍼 복귀 불능이 한 번이라도 재현되면 다음 단계로 진행하지 않는다.
