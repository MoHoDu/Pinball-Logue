# 차원 독립 데이터 조립형 보드와 2D 목업

- 상태: approved
- 관련 결정: `DEC-20260728-02`, `DEC-20260728-03`
- 승인 기록: 2026-07-28 사용자가 58° 2D 목업과 차원 독립 기준을 승인하고, 이어서 마우스 기반 기획자용 보드 제작 도구 전체 구현을 승인함

## 표현 방향

- 최종 그래픽의 2D·3D 선택은 미확정이다.
- 보드 형상·앵커·게임 규칙 데이터는 `Node2D`·`Node3D` 타입을 참조하지 않는다. 보드 평면 좌표는 `Vector2`로 기록하고 2D는 XY, 미래 3D는 XZ 등 표현 어댑터의 평면으로 변환한다.
- 현재 목업은 `BoardMockup2D`가 담당한다. 미래 `BoardView3D`는 같은 `BoardLayoutConfig`와 공개 상태를 소비하는 별도 어댑터로 추가한다.
- 런타임에서 2D와 3D를 동시에 유지하거나 토글하는 기능은 최종 방향 승인 전 구현하지 않는다.

## 보드 평면 데이터 계약

`BoardLayoutConfig`는 보드의 논리 구성만 소유하고, `BoardViewConfig`는 2D 시점·크기·색과 목업 마커 크기만 소유한다.

- 보드 평면 좌표는 중심이 `(0, 0)`이고 좌상단이 `(-0.5, -0.5)`, 우하단이 `(0.5, 0.5)`인 정규화 좌표다.
- 경계는 첫 점을 끝에 반복하지 않은 `PackedVector2Array`로 저장한다. 마지막 점에서 첫 점으로 이어지는 변을 암묵적으로 포함해 폐합한다.
- 현재 데이터 계약은 꼭짓점 3개 이상의 단순 볼록 다각형을 허용한다. 0면적, 연속 중복점, 자기 교차와 오목 경계는 조립 전에 거부한다.
- 경계선 위의 앵커는 유효한 내부 위치로 인정한다.
- `BoardAnchorConfig`는 고유 `anchor_id`, 지원되는 `anchor_type`, 정규화 `board_position`과 평면 회전값 `rotation_degrees`를 제공한다.
- 지원 앵커 종류는 `launch`, `drain`, `bumper`, `flipper`, `relic_slot`, `object`, `track_point`, `shot_target`이다.
- `track_point`는 경로 범퍼가 공을 순서대로 안내할 `경로 지점`, `shot_target`은 발사 범퍼가 공을 내보낼 `발사 목표 지점`이다. 두 지점은 실제 오브젝트 원형을 배치하지 않는 보조 지점이다.
- `launch_anchor_id`와 `drain_anchor_id`는 실제 존재하는 같은 종류의 앵커를 참조해야 한다.
- null 앵커, 빈 ID, 중복 ID, 지원하지 않는 종류, 비유한 좌표와 경계 밖 좌표는 전체 조립을 사전에 거부한다. 일부 요소만 조립하지 않는다.
- 유물 슬롯은 위치만 제공하며 보유·배치 유효성·효과와 D-06의 배치 시점을 결정하지 않는다.

기본 레이아웃은 `stages/boards/default_board_layout_config.tres`에 둔다.

| 종류 | 기본 ID·개수 | 정규화 보드 평면 위치 |
| --- | --- | --- |
| 발사 | `launch_main` 1개 | `(0.38, 0.24)` |
| 드레인 | `drain_main` 1개 | `(0.0, 0.46)` |
| 범퍼 | `bumper_top_left`, `bumper_top`, `bumper_top_right`, `bumper_mid_left`, `bumper_mid_right` 5개 | `(-0.28, -0.28)`, `(0.0, -0.34)`, `(0.28, -0.28)`, `(-0.34, 0.0)`, `(0.34, 0.0)` |
| 플리퍼 | `flipper_left`, `flipper_right` 2개 | `(-0.32, 0.32)`, `(0.32, 0.32)` |
| 유물 슬롯 | `relic_left`, `relic_center`, `relic_right` 3개 | `(-0.18, 0.12)`, `(0.0, 0.18)`, `(0.18, 0.12)` |

- 기본 경계는 정규화 사각형 `(-0.5,-0.5) → (0.5,-0.5) → (0.5,0.5) → (-0.5,0.5)`이다.
- 발사점과 드레인 사이의 직선이 경계 안에 머무는지를 데이터 단계의 결정적 경로 확인으로 사용한다. 이는 실제 공의 물리적 도달 가능성을 의미하지 않으며 4단계 이후 별도 검증한다.
- 기본 앵커 개수와 위치는 최종 밸런스가 아니라 3단계 조립·교체 검증용 초기값이다. 기본 `.tres` 대신 복제본을 주입해 비교한다.

## 기본 시점

- 첨부 레퍼런스처럼 보드 상단이 좁고 하단이 넓게 보이는 경사 원근을 사용한다.
- `view_angle_degrees` 기본값은 보드 평면 기준 58°다. 90°에 가까울수록 탑다운 직사각형에 가까워지고 값이 낮을수록 상단 폭이 좁아진다.
- 2D 목업은 이 각도를 사다리꼴 상단 폭과 세로 압축으로 변환한다.
- 미래 3D 어댑터는 같은 값을 카메라 또는 보드 기울기 설정으로 해석하되 시각 결과가 2D 기준과 유사한지 비교한다.
- 2D 어댑터는 정규화 보드 좌표에 `board_size`를 적용하고, 위쪽 폭 비율과 세로 압축을 모든 경계점·앵커에 동일하게 적용한다.

## 편집 가능한 설정

기본 설정은 `stages/boards/default_board_view_config.tres`에 둔다.

| 속성 | 기본값 | 용도 |
| --- | --- | --- |
| `view_angle_degrees` | 58° | 레퍼런스 기준 보드 시점 |
| `board_size` | 540×500 px | 정규화 보드 평면을 표시하는 2D 목업의 기준 폭·길이 |
| `rail_width` | 18 px | 외곽 레일 두께 |
| 색상 속성 | 기본 목업 팔레트 | 보드·레일·범퍼·강조 표시 |

- 모든 값은 Godot Inspector에서 수정하고 Resource를 복제해 비교 테스트할 수 있다.
- 설정 검증은 각도 20~85°, 양수 보드 크기와 레일 두께를 요구한다.
- 범퍼·플리퍼·발사·드레인·유물 슬롯의 위치와 개수는 `default_board_layout_config.tres` 복제본에서 수정한다.

## 2D 조립 경계

- `BoardMockup2D`는 유효한 레이아웃 전체를 한 번에 투영하며, 오류가 있으면 공개 검증 결과로 조립을 거부한다.
- 외곽선은 레이아웃의 마지막 꼭짓점과 첫 꼭짓점을 연결해 표시한다.
- 보드 제작·조립 화면에는 실제 공을 두지 않고 발사 지점 표식만 표시한다. 공 종류·원형·능력과 활성 공은 `pinball/ball`의 후속 런타임이 소유한다.
- 보스 표시 위치와 실제 물리·충돌·스코어·유물 효과는 각각 후속 보스·핀볼·유물 단계의 책임이며 이번 데이터 계약에 포함하지 않는다.
- 웨이브·보스 화면의 `Node2D` 루트, 진행 버튼과 화면 전환 계약은 변경하지 않는다.

## 기획자용 보드 제작 도구

- 기획자는 `BoardAuthoring2D` 제작 씬을 열고 별도 스크립트 실행 없이 Godot 2D 화면에서 작업한다.
- 외곽선 정점은 화면 손잡이를 마우스로 이동하고, 배치 지점은 제작 도구의 한국어 버튼으로 추가한 뒤 화면에서 이동한다.
- 경로 범퍼의 `경로 지점`과 발사 범퍼의 `발사 목표 지점`도 제작 도구의 한국어 버튼으로 추가하고 2D 화면에서 마우스로 이동한다.
- 모든 마우스 편집은 Godot 실행 취소·다시 실행 기록에 포함한다.
- 변경 결과는 현재 58° 2D 조립 미리보기에 즉시 반영하고 저장·닫기·재열기 뒤에도 유지한다.
- 공유 기본 파일을 직접 바꾸지 않도록 `복제해서 새 보드 만들기`를 첫 작업으로 제공한다.
- 오류는 하단 출력만 사용하지 않고 제작 화면과 문제가 있는 지점에 원인과 해결 방법을 한국어로 표시한다.
- 편집 화면에서 노출하는 이름은 `보드 외곽선`, `배치 지점`, `웨이브 배치`, `오브젝트 원형`, `2D 디자인`, `유물 배치 지점`, `발사 지점`, `경로 지점`, `발사 목표 지점`을 사용한다.
- 제작 씬 루트의 변형은 위치 `(0, 0)`, 회전 `0`, 크기 `(1, 1)`을 유지한다. 단독 실행 화면 중앙 배치는 자식 카메라 또는 표현 기준 노드가 담당해 다른 씬의 인스턴스로 사용해도 루트 변형 경고가 없어야 한다.
- 새 보드는 `res://stages/boards/content/<board_id>/` 아래에 `<board_id>_layout.tres`와 `<board_id>_wave_composition.tres`를 함께 저장한다. 영문 소문자·숫자·밑줄 식별자만 허용하며 기존 다른 경로의 복제본은 계속 읽는다.
- 기본 템플릿과 기존 복제본은 자동 이동하거나 덮어쓰지 않는다. 같은 ID 폴더·파일이 있으면 사용자 확인 없이 저장하지 않는다.
- 제작 씬을 선택한 직후부터 기존 지점을 클릭·이동할 수 있으며, 플리퍼는 제작 도구에서 안쪽 방향 맞춤과 좌우 회전을 제공한다.
- 제작 도구는 현재 보드의 표시 크기 증감과 현재 웨이브 배치를 디버그 웨이브 시험 보드로 지정하는 조작을 같은 패널에 제공한다.
- 경로 범퍼 또는 발사 범퍼를 적용할 때 필요한 경로 지점 또는 발사 목표 지점이 없으면 오류만 표시하지 않고 이동 가능한 기본 보조 지점을 함께 만든다.

## 인스펙터 한국어 표시

- GDScript 변수명과 `.tres` 직렬화 속성명은 영문을 유지한다.
- Godot 인스펙터에는 설정별 한국어 표시 이름, 쉬운 설명, 단위와 허용 범위를 제공한다.
- 기존 `BoardLayoutConfig`, `BoardAnchorConfig`, `BoardViewConfig`, `WaveBoardCompositionConfig`, 배치·오브젝트 원형과 이후 공·발사 설정이 같은 표시 메타데이터 계약을 사용한다.
- 한국어 표시는 저장 속성을 복제하지 않고 원래 영문 속성을 편집해야 하며, 플러그인을 비활성화해도 `.tres` 데이터가 손상되지 않아야 한다.

## 배치 지점과 웨이브 배치 분리

- 보드 템플릿은 외곽선과 빈 배치 지점만 소유한다. 배치 지점은 고유 이름, 허용 역할, 보드 위치와 회전을 제공한다.
- 웨이브 배치는 배치 지점 이름과 오브젝트 원형 ID를 연결한다. 같은 보드 템플릿에 여러 웨이브 배치를 적용할 수 있다.
- 배치 콘텐츠가 없는 지점은 유효한 빈 지점으로 유지하며 실제 2D 디자인을 생성하지 않는다.
- 범퍼·벽·일반 오브젝트와 플리퍼는 고정 웨이브 배치에 사용할 수 있다.
- 유물 배치 지점은 허용 조건과 위치만 제공한다. 에디터 미리보기용 유물 원형은 표시할 수 있지만 실제 플레이의 유물 점유는 `relics/placement`가 소유한다.
- 지점 역할과 오브젝트 종류 불일치, 중복 배치, 존재하지 않는 지점·원형과 깨진 표현 참조는 전체 조립 전에 거부한다.

## 플리퍼 외곽선 배치

- 한 웨이브의 플리퍼 배치 지점은 1~4개다.
- 플리퍼 지점은 자유 좌표 대신 외곽선 변 번호와 변 위의 0~1 위치 비율을 기준으로 저장한다.
- 마우스로 이동할 때 가장 가까운 외곽선으로 붙이고 플리퍼 기본 방향을 보드 안쪽으로 맞춘다.
- 외곽선 정점이 바뀌어도 같은 변의 위치 비율을 다시 계산해 플리퍼를 외곽선에 유지한다.
- 모서리를 넘어 다음 변으로 이동할 때 끊김이나 순간 이동이 없어야 한다.
- 서로 겹치거나 드레인을 막는 플리퍼 배치는 오류 또는 명확한 경고로 표시한다.

## 오브젝트 원형과 표현 경계

- 배치 지점과 웨이브 배치는 `PackedScene`, `Node2D`, `Node3D`를 직접 소유하지 않고 차원 독립 오브젝트 원형 ID를 사용한다.
- 오브젝트 원형은 각 소유 기능에서 종류, 범퍼 하위 종류, 최대 내구도와 같은 규칙 데이터를 제공한다.
- 현재 2D 디자인 연결표는 오브젝트 원형 ID를 신뢰된 2D 재사용 장면에 연결한다. 미래 3D 연결표는 같은 ID를 별도 3D 장면에 연결한다.
- 최종 차원 확정 전 2D·3D 동시 실행이나 런타임 토글은 구현하지 않는다.
- 최대 내구도와 충돌 반응은 범퍼 원형 데이터, 현재 내구도와 접촉 잠금은 생성된 런타임 인스턴스가 소유한다. 경로·발사 목표처럼 보드마다 달라지는 위치는 웨이브 배치가 보조 지점 ID로 연결한다.

## 수용 기준

1. 기본 설정에서 상단이 좁고 하단이 넓은 58° 2D 보드 목업과 기본 앵커 구성이 웨이브·보스 화면에 표시된다.
2. 복제 `.tres`의 시점 각도·경계·앵커 위치·개수를 바꾸면 코드 변경 없이 2D 조립 결과가 달라지고 기본 리소스는 보존된다.
3. 잘못된 시점·크기·경계·앵커·참조는 검증 오류를 반환하고 부분 조립하지 않는다.
4. 경계가 암묵적으로 폐합되고 기본 발사점→드레인 직선이 경계 안에 머문다.
5. `BoardLayoutConfig`와 `BoardAnchorConfig`는 `Node2D`·`Node3D` 및 화면·진행 코드에 의존하지 않는다.
6. 웨이브·보스 화면 전환과 진행 상태는 기존과 동일하게 유지된다.
7. 실제 공 이동, 플리퍼 개입, 충돌·스코어, 유물 위치 효과와 경로별 성공률은 후속 단계 전까지 `미측정`으로 남긴다.
8. 비개발자가 GDScript·파일 직접 편집·좌표 계산 없이 복제→외곽선 편집→지점 추가·이동→원형 지정·교체→플리퍼 이동→저장·실행 확인을 완료한다.
9. 마우스 편집은 Undo/Redo와 저장·재열기를 통과하고, 잘못된 구성은 부분 조립하지 않으며 제작 화면에서 한국어로 해결 방법을 안내한다.
10. 같은 보드 템플릿의 서로 다른 웨이브 배치가 독립적인 오브젝트 구성을 만들고, 원형 교체는 지점 위치·회전을 바꾸지 않는다.
11. 플리퍼 1~4개는 외곽선을 따라 이동하고 경계 변경 뒤에도 붙어 있으며, 0개와 5개 이상은 거부한다.
12. 보드 데이터·웨이브 배치·제작 씬과 미리보기에 공 원형·공 종류·활성 공 참조가 없고 발사 지점만 남는다.
13. 새 보드 복제는 표준 콘텐츠 폴더에 설계도·보기 설정·웨이브 배치표를 함께 저장하고 기존 복제본은 이동·변경하지 않는다. 보드 표시 크기는 복제한 보드별 보기 설정에서만 바꾼다.
14. 제작 씬 루트 변형 경고가 없으며 단독 실행과 다른 씬 인스턴스에서 같은 보드 중심을 유지한다.
15. 인스펙터 한국어 이름으로 값을 바꿔도 원래 영문 속성 하나만 변경·직렬화되고 저장·재열기 뒤 값이 유지된다.
